Stillfeed is a Bun + TypeScript application with a React UI; there is no Python. SQLite (bun:sqlite) is the only runtime state: articles, seen marks, saved items, sources, X accounts, settings, feed batches, personal Hot ratings, suggestions, cached readings and summaries, model decisions.

Server and processes: src/server.ts serves the API and the UI, schedules collections internally (src/server.ts nextRefresh; every N hours with an optional 23:00–05:00 night pause) and spawns a collection (`--collect`, src/collect.ts), the reader worker (src/reader_worker.ts), which downloads and sanitizes articles and batches summaries, a dedicated chat worker (src/chat_worker.ts), which answers persisted questions without waiting for reader preparation, and a personal selection worker (src/personal_worker.ts). Chat history and jobs are SQLite tables in src/chat.ts; HTTP handlers only snapshot cached context and enqueue. Web requests only read cached preparation results or enqueue high-priority jobs; never run a model in an HTTP handler. Saved items are exempt from retention, including their cached content. Collection leases record the owning PID and token so a killed process cannot leave refresh blocked. Read-then-write worker transactions acquire the SQLite writer lock before reading (immediate transactions).

Collection (src/collect.ts): RSS/Atom/JSON feeds (src/feeds.ts), YouTube channels through youtubei.js (src/youtube.ts), X through SocialData (fetchTweets, records in src/tweets.ts) and nine web collectors (src/web.ts) run side by side, then classify(): trusted AI sources, the keyword filter (src/relevance.ts), the data-engineering signal, and the model triage (src/triage.ts, decisions cached in model_decisions). Feed categories are independent AI/Data flags (`articles.ai_topic` / `data_topic`); `Filters.categories` combines selected categories with OR, and an empty selection means Everything. Legacy `scope=ai` means both categories; browser preferences and frozen batches migrate without changing membership. Model triage returns separate AI/Data lists and caches both; Saved ignores category restrictions. Phase timings are logged as 'timing <phase>'. Suggestions run after a collection and must never fail it. Hot is rated independently by the personal worker in bounded batches from the active Feed snapshot only; accepted results have no fixed quota. Positive and negative ratings are cached per interest profile, with a lease and retry state; HTTP handlers only read ratings or save interests. Interests are seeded from STILLFEED_INTERESTS, then edited in settings and shared with source suggestions.

AI (src/llm.ts): one complete(prompt, role) for Anthropic (@anthropic-ai/sdk, server-side fallback for the families that support it), OpenAI-compatible APIs (openai) and the codex CLI. Only Discuss passes web: true: Anthropic gets hosted web search/fetch; codex keeps its lockdown (no shell, MCP servers, goals or image generation, read-only sandbox) and enables only the ChatGPT search app, never other connected apps. Every other call runs without tools. No provider means Unavailable: articles are still prepared, summaries/Hot/suggestions stay off. Prompts write in STILLFEED_LANGUAGE; summaries are cached per content hash and language. Configuration is src/config.ts (STILLFEED_HOME/.env, environment wins); never print secrets.

Sources (src/sources.ts): defaults from feeds/follow.opml, feeds/channels.json and feeds/x-accounts.txt, plus the user's feeds.opml and x-accounts.txt, each added once (table seeded), so a removed or disabled source stays that way. The Sources page (/sources, ui/sources.tsx) adds a feed, site (autodiscovery) or YouTube channel by URL, follows X accounts, and finds, switches and removes every source; the drawer only links to it.

UI: React (ui/main.tsx, ui/app.tsx, ui/card.tsx, ui/detail.tsx, ui/sources.tsx, ui/sidebar.tsx), interface strings in ui/i18n.ts. Before using UI SDK, read node_modules/@ui-sdk/react/docs/llms.txt and the relevant component docs; use its ready-made components. The detail swipes back using motion's drag (dragControls started from onPointerDown after gestureAllowed, so controls and screen edges never start a drag); saving is the bookmark button with an Undo toast; feed swipes switch adjacent tabs (Hot, Feed, Saved) without wrapping, and share direction-locked plain touch events with pull to refresh so vertical scrolling stays native. Keep touch-action pan-y pinch-zoom on .reader, #feed and #articlePage. Controls are monochrome (colour belongs to content); options live in a right-hand Drawer whose controls apply immediately. The detail and Sources are pages with their own URL over the mounted feed; Back returns to the same place (after source changes the feed is rebuilt from the top). Releasing the drawer's scroll lock can move the page on phones, so keepReadingPosition restores the reading position on that one <html> style change. New data is always offered by a pill and never replaces the snapshot automatically.

Seen workflow: seen marks record visibility only. Rows never leave automatically after opening an article, returning to the app, reloading, or new data arriving. The counter shows one number, the unseen rows in the current batch, which falls as rows are seen. It stays at the right of the pinned single-row header, with a chevron that indicates its action menu. Tapping it explains the unseen, seen and batch counts and offers Hide seen; that action and the footer button explicitly dismiss seen rows, with Undo; bookmarks remain saved. Dismissals persist in SQLite across refreshes and devices. The batch size excludes dismissed rows (3 of 103 seen becomes 0 of 100), so Hide seen leaves the unseen number unchanged; snapshot ordinals remain stable for pagination. A fresh batch adds new matching rows to older outstanding rows from the explicitly managed feed queue. Historical snapshots and Hot never seed that queue. Queue version 2 recovers the last explicitly dismissed Feed batch (or the prior legacy view), invalidates old counters and keeps current source, category, format and search filters. New collections are offered via a pill, including at the top; replacing the snapshot requires a user action. Hot is a subset of the specific Feed snapshot (filters.personalBatch), including its filters and hidden state. The worker and result query both restrict IDs to that parent batch; new collections enter Hot only after entering the Feed snapshot. Hot uses the same pagination, seen counter and explicit Hide seen as Feed. Reading never removes a row. Hide seen dismissals apply to both tabs; there is no separate Not interested action. Bookmarks are independent. Hot has no count badge in the header.

Verify with bun install --frozen-lockfile, bun run check, bun test src and bun run build; commit bun.lock and the generated assets/build/ and index.html (scripts/build.ts: code-split, content-hashed bundles served as immutable, stylesheet inlined). Keep the first paint small: the reader, settings and dialogs load lazily; bun run test:perf enforces the budgets. Browser tests (tests/ui.mjs) use an isolated state directory and a stub collection; never touch a real Stillfeed home in a test.
