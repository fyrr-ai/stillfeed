Stillfeed is a Bun + TypeScript application with a React UI; there is no Python. SQLite (bun:sqlite) is the only runtime state: articles, seen marks, saved items, sources, X accounts, settings, feed batches, Hot picks, suggestions, cached readings and summaries, model decisions.

Server and processes: src/server.ts serves the API and the UI, schedules collections internally (src/server.ts nextRefresh; every N hours with an optional 23:00–05:00 night pause) and spawns a collection (`--collect`, src/collect.ts), the reader worker (src/reader_worker.ts), which downloads and sanitizes articles and batches summaries, and a dedicated chat worker (src/chat_worker.ts), which answers persisted questions without waiting for reader preparation. Chat history and jobs are SQLite tables in src/chat.ts; HTTP handlers only snapshot cached context and enqueue. Web requests only read cached preparation results or enqueue high-priority jobs; never run a model in an HTTP handler. Saved items are exempt from retention, including their cached content.

Collection (src/collect.ts): RSS/Atom/JSON feeds (src/feeds.ts), YouTube channels through youtubei.js (src/youtube.ts), X through SocialData (fetchTweets, records in src/tweets.ts) and nine web collectors (src/web.ts) run side by side, then classify(): trusted AI sources, the keyword filter (src/relevance.ts), the data-engineering signal, and the model triage (src/triage.ts, decisions cached in model_decisions). Phase timings are logged as 'timing <phase>'. Hot and suggestions run after a collection and must never fail it.

AI (src/llm.ts): one complete(prompt, role) for Anthropic (@anthropic-ai/sdk, server-side fallback for the families that support it), OpenAI-compatible APIs (openai) and the codex CLI. No provider means Unavailable: articles are still prepared, summaries/Hot/suggestions stay off. Prompts write in STILLFEED_LANGUAGE; summaries are cached per content hash and language. Configuration is src/config.ts (STILLFEED_HOME/.env, environment wins); never print secrets.

Sources (src/sources.ts): defaults from feeds/follow.opml, feeds/channels.json and feeds/x-accounts.txt, plus the user's feeds.opml and x-accounts.txt, each added once (table seeded), so a removed or disabled source stays that way. The Sources page (/sources, ui/sources.tsx) adds a feed, site (autodiscovery) or YouTube channel by URL, follows X accounts, and finds, switches and removes every source; the drawer only links to it.

UI: React (ui/main.tsx, ui/app.tsx, ui/card.tsx, ui/detail.tsx, ui/sources.tsx, ui/sidebar.tsx), interface strings in ui/i18n.ts. Before using UI SDK, read node_modules/@ui-sdk/react/docs/llms.txt and the relevant component docs; use its ready-made components. The detail swipes back using motion's drag (dragControls started from onPointerDown after gestureAllowed, so controls and screen edges never start a drag); saving is the bookmark button with an Undo toast; feed swipes switch adjacent tabs (Hot, Feed, Saved) without wrapping, and share direction-locked plain touch events with pull to refresh so vertical scrolling stays native. Keep touch-action pan-y pinch-zoom on .reader, #feed and #articlePage. Controls are monochrome (colour belongs to content); options live in a right-hand Drawer whose controls apply immediately. The detail and Sources are pages with their own URL over the mounted feed; Back returns to the same place (after source changes the feed is rebuilt from the top). Releasing the drawer's scroll lock can move the page on phones, so keepReadingPosition restores the reading position on that one <html> style change. New data is always offered by a pill and never replaces the snapshot automatically.

Seen workflow: seen marks record visibility only. Rows never leave automatically after opening an article, returning to the app, reloading, or new data arriving. The seen/current-batch counter stays at the right of the pinned single-row header, with a chevron that indicates its action menu. Tapping it explains both numbers and offers Hide seen; that action and the footer button explicitly dismiss seen rows, with Undo; bookmarks remain saved. Dismissals persist in SQLite across refreshes and devices. The denominator excludes dismissed rows (3/103 becomes 0/100); snapshot ordinals remain stable for pagination. A fresh batch adds new matching rows to older outstanding rows from prior feed snapshots, while current source, scope, format and search filters still apply. New collections are offered via a pill, including at the top; replacing the snapshot requires a user action. Hot picks leave only when opened or dismissed, never by being on screen.

Verify with bun install --frozen-lockfile, bun run check, bun test src and bun run build; commit bun.lock and the generated assets/build/ and index.html (scripts/build.ts: code-split, content-hashed bundles served as immutable, stylesheet inlined). Keep the first paint small: the reader, settings and dialogs load lazily; bun run test:perf enforces the budgets. Browser tests (tests/ui.mjs) use an isolated state directory and a stub collection; never touch a real Stillfeed home in a test.
