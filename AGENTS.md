Radar is a Bun + TypeScript application. SQLite is the only runtime source for articles, seen state, sources, settings and feed batches. Native RSS/Atom/JSON Feed and X collection writes SQLite transactionally. Python adapters provide web collection and relevance. Legacy JSON is imported only once. The reader worker downloads and sanitizes articles and batches Czech summaries through gpt-6-luna. Web requests only read cached preparation results or enqueue high-priority jobs; never run a model in an HTTP handler. Saved items are exempt from retention, including their cached content. The UI is React (ui/main.tsx, ui/app.tsx, ui/card.tsx, ui/detail.tsx). Before using UI SDK, follow its skill if installed and read node_modules/@ui-sdk/react/docs/llms.txt and the relevant component docs; use its ready-made React components. The only swipe is back from the detail, using motion's drag (dragControls started from onPointerDown after gestureAllowed, so controls and screen edges never start a drag); saving is the bookmark button only, by the user's choice; pull to refresh uses plain touch events because it must cooperate with native scrolling. Keep touch-action pan-y pinch-zoom on #feed and #articlePage. Run bun install --frozen-lockfile, bun run check, bun test src and bun run build. Commit bun.lock and generated assets/main.js. Browser/data coverage verification lives in tests/radar-ui.mjs at the repository root and must use an isolated state directory. Never change live seen marks in a test.

Typography uses named roles in assets/styles.css, with a system sans stack on phones and complete Geist Latin/Latin Extended fallbacks. Keep full post text; article previews may clamp because their full titles are available in the reader. Browser verification checks Czech glyph coverage, 200% text sizing and native scrolling alongside the drag gestures.

The UI is deliberately dense: :root font-size is 90 % and the card avatar column is 34 px; keep 44 px hit areas for buttons.

Seen workflow: hideSeen is the default; a snapshot (batch) never changes under the reader. Seen items leave on the next fresh load (open, pull to refresh, return after 15 min); an opened article leaves on return and is remembered per snapshot (session.collapsed). Hot (src/hot.ts, scripts/hot.py) picks at most 10 active items after each collection from ~/.config/rmt/radar-interests.md; picks leave only when opened (opened table) or dismissed (hot_dismissed), never by being on screen. Hot failures must never fail a collection.

Videos and Reddit are articles: the reader uses a YouTube transcript (scripts/transcript.py) or the feed's own content (Reddit always; any site as a fallback). Reddit feeds are fetched one at a time 12 s apart. Suggested sources (src/suggest.ts) count distinct citing sources, only treat aggregators' links as site candidates, require a working RSS feed, and are added only on the user's Add; ignored and added keys never return.

Controls are monochrome (black, white, greys; colour belongs to content). Options live in a right-hand UI SDK Drawer (ui/sidebar.tsx) whose controls apply immediately. Releasing the drawer's scroll lock can move the page on phones, so keepReadingPosition restores the reading position on that one <html> style change. New data replaces the snapshot automatically only while the reader is at the top; further down a pill offers it.

Collection saves in two steps: RSS, YouTube, X and the web scrapers first (about 30 s), then Reddit, which is fetched one subreddit at a time 12 s apart without retries. Phase timings are logged as 'timing <phase>'. X Articles get title/preview/cover from the public embed API at collection time and their full text from SocialData's v2 article endpoint in the reader worker.
